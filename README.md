# EKT Assistant

Расширение Google Chrome Manifest V3, сервер Node.js и адаптивный веб-стенд для ассистента ekt.kz. Реальный API каталога подключён. Изменение настоящей корзины **имитируется через `alert` по согласованному сценарию**; есть отдельная серверная демонстрационная корзина с прямой ссылкой.

## Быстрый запуск

Нужен Node.js 22.18+.

```powershell
npm.cmd install
# Только при первоначальном развёртывании, если .env ещё нет:
Copy-Item .env.example .env
npm.cmd start
```

Откройте **http://localhost:8787**. В текущем рабочем каталоге `.env` уже подготовлен для реального API. Не перезаписывайте его командой копирования. `npm.cmd` позволяет запускать npm в PowerShell без изменения политики выполнения скриптов.

В `.env` задайте `DATA_MODE=live`, `EKT_API_USER` и `EKT_API_PASSWORD` для реального каталога. `DATA_MODE=demo` включает 8 синтетических товаров для воспроизводимой демонстрации всех основных сценариев. **Не публикуйте `.env`**: он исключён из Git; HTTP-сервер его не раздаёт.

Ключ `OPENAI_API_KEY` добавляется **только в `.env` на сервере**. Пока ключ пуст, платных вызовов нет; поиск, характеристики, условия и подтверждение работают. После изменения `.env` перезапустите сервер.

## Установка расширения

1. Запустите сервер.
2. Откройте `chrome://extensions`, включите режим разработчика, нажмите «Загрузить распакованное расширение» и выберите папку `extension`.
3. Откройте настройки расширения: укажите `http://localhost:8787` либо HTTPS-адрес вашего сервера. Скопируйте показанную строку `chrome-extension://...` в `EXTENSION_ORIGINS` серверного `.env`, перезапустите сервер.
4. Откройте или обновите `https://ekt.kz`. Внизу справа появится кнопка «Спросить ассистента».

В расширении нет ключей и паролей. Content script добавляет только изолированное окно. Запросы выполняет service worker с ограниченным списком серверных маршрутов; API ekt.kz и OpenAI вызываются сервером. Для своего HTTPS-сервера разрешение запрашивается только при сохранении его адреса.

Мобильный сценарий — адаптивная веб-страница на том же сервере или внедрение виджета владельцем сайта. Установка этого десктопного расширения в мобильный Chrome не является частью прототипа. Веб-стенд удобно открыть на телефоне после размещения на HTTPS-сервере.

## Архитектура

```text
ekt.kz → content script → iframe расширения → service worker
                                                    ↓
Мобильная / демонстрационная веб-страница → Node.js API
                                             ├─ EKT API: Basic Auth, только сервер
                                             ├─ локальное чтение PDF / DOCX / XLSX
                                             ├─ OpenAI: ограниченное распознавание запроса / фото
                                             └─ предложение → подтверждение → проверка → demo cart → alert
```

- `server/catalog.js` — синтетический каталог, поиск и проверенные тестовые аналоги.
- `server/live-catalog.js` — адаптер предоставленного API, пагинация, детальные карточки, нормализация полей.
- `server/assistant.js` — сценарии диалога и правила изменения корзины.
- `server/ai.js` — Responses API со строгой JSON-схемой. Модель возвращает намерение, поисковую строку и количество; она не генерирует цены, остатки и подтверждения.
- `server/uploads.js`, `upload-worker.js` — обработка вложений в worker с ограничением памяти и времени.
- `extension/` — готовое распакованное расширение и общий интерфейс чата.
- `web/` — демонстрационный сайт и просмотр текущей демо-корзины.
- `tests/` — сценарии безопасности, остатки, адаптер и чтение файлов.

## Реальные данные и их границы

Проверенные адреса партнёра:

- `GET https://ekt.kz/api/products?page=1` — `{page, per_page, count, items}`.
- `GET https://ekt.kz/api/products/detail?id=515291` — товар, `price`, `quantity`, `stores`, `properties`, описание, изображение и ссылка.

Сервер передаёт Basic Auth только на `https://ekt.kz/api`, запрещает перенаправления авторизованных запросов. Товары из списка сначала имеют неизвестный остаток; перед ответом по найденному товару запрашивается детальная карточка. Источник не подменяется синтетическими данными при ошибке.

По умолчанию при старте загружаются первые **10 страниц / до 200 товаров** и контрольный товар `515291`. Поиск работает по загруженной выборке. `EKT_MAX_PAGES` позволяет расширить её; в прототипе синхронизация не сохраняется между перезапусками. Поиск по ID (`515291`, `товар 515291`, `id=515291`) позволяет запросить карточку вне выборки. Отсутствие совпадения не означает отсутствие товара на сайте. Нет документированного API поиска по произвольному артикулу — для полного каталога нужен полный индекс/выгрузка.

В контрольном товаре выявлено расхождение: название содержит 160 А, `NOMINALNYY_TOK` — 250 А. Виджет показывает предупреждение, не исправляет источник предположениями. Остаток берётся из общего поля `quantity`; распределение по складам показывается отдельно. API не документирует единицу продажи, поэтому реальные товары показываются в «ед.», минимальное количество — `KRATNOST_MIN` (при отсутствии — техническое значение прототипа 1).

В проверенных ответах нет отдельного поля сертификатов и подтверждённой связи аналогов. Поэтому реальные сертификаты и эквивалентность товаров не выдумываются. В демо-режиме есть ссылка на явно помеченный образец документа и аналог `DEMO-102 → DEMO-101` по одинаковым критическим характеристикам. `RECOMMEND` из API не трактуется как список аналогов.

Условия покупки взяты из [официальной страницы ekt.kz](https://ekt.kz/checkout-delivery/), проверенной 23.09.2026, и вынесены в `server/conditions.js`. Страница содержит противоречивые пороги бесплатной доставки; ответ сообщает об этом и направляет за уточнением. Снимок условий нужно актуализировать перед публичным запуском.

## Подтверждение и имитация корзины

1. Пользователь выбирает товар и целое количество, нажимает «В демо-корзину» или пишет `добавь DEMO-101 2 шт`.
2. Сервер проверяет остаток, учитывая уже добавленное количество, и создаёт предложение на 5 минут. Корзина пока не меняется.
3. Пользователь нажимает **«Да, добавь»** или отправляет ровно `да, добавь` / `подтверждаю` / `да, добавить`.
4. Сервер проверяет принадлежность предложения сессии, срок, цену и актуальный остаток. Повторное подтверждение того же ID не добавляет количество повторно.
5. Обновляется демо-корзина, появляется ссылка и вызывается `notifyCartChange(result)` в `extension/widget.js`: согласованный `alert` о добавлении.

`notifyCartChange` — место замены на настоящую функцию корзины при внедрении в сайт. Для боевого подключения эта функция должна вызывать серверный адаптер корзины с авторизацией конкретного посетителя, защитой CSRF, повторной проверкой предложения и идемпотентностью. Нельзя доверять клиентскому событию или общему Basic Auth как авторизации корзины посетителя. Сейчас никаких запросов изменения настоящей корзины ekt.kz нет.

Любой новый вопрос отменяет предыдущий контекст подтверждения. Текст вложения и ответ модели никогда не подтверждают добавление. Обычное «да» недостаточно. Количество не урезается молча: превышение остатка возвращает ошибку. Заказы и платежи отсутствуют.

Прямая ссылка на демо-корзину содержит случайный **токен только для чтения** в URL-фрагменте. Она показывает текущее состояние сессии; токен не разрешает изменения. Не публикуйте ссылку, если содержимое корзины конфиденциально. Сессия живёт 2 часа в памяти сервера, сбрасывается при перезапуске; кнопка ↻ удаляет её и корзину.

## Экономия OpenAI и вложения

Поиск по каталогу, ответы по карточкам, условия и подтверждения обходятся без LLM. OpenAI нужен только для нераспознанного запроса и фото. Используется настраиваемый `gpt-4.1-mini`, максимум 600 выходных токенов, короткий контекст, `store:false`, тайм-аут 12 секунд, без автоматических повторов.

Бюджет в `.runtime/ai-budget.json` резервируется **перед вызовом** и сохраняется между перезапусками. Лимиты: 30 запросов в сутки, 6 на сессию, 60 000 резервируемых токенов. Консервативная резервация — 24 000 токенов на вызов (это потолок учёта, не фактический расход); с настройками по умолчанию пройдут **до двух** платных вызовов за сутки. При необходимости увеличьте `AI_DAILY_TOKEN_LIMIT`. Отдельный проектный лимит расходов задайте в аккаунте OpenAI. Файл бюджета рассчитан на **один процесс сервера**; несколько реплик требуют общего атомарного счётчика.

PDF, DOCX и XLSX читаются локально; файлы не сохраняются на диск. Ограничения: 5 МБ, 12 секунд, 192 МБ heap worker, до 25 МБ распакованного Office-архива; первые 10 PDF-страниц, 3 Excel-листа, 150 строк/14 столбцов, 5000 символов текста. Сканы PDF без текстового слоя нужно отправлять изображением. Старые `.doc`/`.xls` нужно пересохранить в `.docx`/`.xlsx`. JPEG/PNG проверяются декодером, уменьшаются до 1000×1000 и перекодируются без исходных метаданных. Распознавание фото требует ключа OpenAI; совпадение всегда предварительное.

Если поиск в документе не нашёл артикул локально, ограниченный извлечённый текст может попасть в OpenAI; фото отправляется в OpenAI при включённом ключе. Не отправляйте платёжные или персональные данные. `store:false` не является заявлением о полном отсутствии технического хранения у провайдера. История сообщений остаётся в интерфейсе; сервер держит лишь короткий контекст текущего запроса и найденные позиции, не пишет тексты или вложения в журналы.

## Проверка

```powershell
npm.cmd test
npm.cmd run check
```

Тесты не обращаются к OpenAI и не тратят токены. Проверяют поиск, цены и характеристики, аналоги, условия, обязательность подтверждения, истечение предложения, повторные нажатия, изменение цены/остатка, превышение количества, изоляцию сессий, происхождение запросов, токен просмотра корзины и вложения.

Для реального API: `node --env-file=.env scripts/inspect-api.js` (читает только каталог, ключи не печатает). После запуска `/api/health` показывает режим, число загруженных товаров и состояние синхронизации.

Демо-сценарий: `DEMO-101` → характеристики/документ → `DEMO-102` → аналог → «Какая доставка?» → `добавь DEMO-101 2 шт` → «да, добавь» → alert → ссылка на корзину. Реальный сценарий: `515291` → остатки/предупреждение → выбрать количество → подтвердить → alert.

## Перед публикацией

Текущая версия — локальный прототип с анонимными сессиями и ограничением запросов по IP, а не публичный production-сервис. Для общего сервера нужны HTTPS, авторизация/квоты посетителей, хранилище сессий и атомарных бюджетов, проверенный полный индекс каталога, утверждённая матрица аналогов и источник сертификатов. Reverse proxy должен ограничивать тело и частоту запросов; код не доверяет произвольному `X-Forwarded-For`.

Визуальная проверка через управляемый браузер в текущей среде недоступна; расширение нужно проверить после загрузки в ваш Chrome. Реальный API и серверные сценарии проверены отдельно. Платные вызовы OpenAI не выполнялись.

Реализация опирается на [OpenAI Docs: Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs), [GPT-4.1 mini](https://developers.openai.com/api/docs/models/gpt-4.1-mini), [Chrome: content scripts](https://developer.chrome.com/docs/extensions/develop/concepts/content-scripts) и [запросы из расширений](https://developer.chrome.com/docs/extensions/develop/concepts/network-requests).
